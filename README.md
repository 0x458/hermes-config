# Hermes 自主执行配置与启动优化

保存 2026-10-18（Asia/Shanghai）已验证的配置修改、恢复补丁和可复用健康观察技能。文件来自已部署实例的脱敏导出；这是配置与补丁存档，不是完整 Hermes 安装或完整灾备。

## 适用版本

- Hermes v0.22.2 (2026.9.24)
- 基础源码提交：`d923a5eb487a17c0a68801bba9ef0f56c81040a8`
- 实测模型：`gpt-6-astra`，provider `openai-codex`，reasoning `high`；优化未改变模型或推理强度。
- 健康观察技能依赖 Linux、Python 3、用户级 `hermes-gateway.service` 和运行中的 Hermes cron。

## 参数含义

- `approvals.mode: off`，以及 cron、单次查询、无人值守的 `approve` 策略，消除本次授权范围内的命令审批等待；行为规则仍要求遵守任务授权边界。
- `agent.max_turns: 300` 为较长任务提供回合预算。
- 重启排空 30 秒、cron 排空 40 秒、启动恢复排空 30 秒，为进行中的任务留出结束和恢复时间。
- `gateway_auto_continue_freshness: 86400` 设置 24 小时续跑窗口；补丁使异常退出标记回收同样尊重此窗口。
- 开启 checkpoint、错过调度补跑和代理自主调度；cron 最大并行数 2，要求可安全重启的任务范围。

`mode: off` 会关闭命令交互审批。应仅合并到用户明确授权的部署环境；它不是系统级权限隔离。

## 应用与恢复

1. 先备份目标实例的 `config.yaml`、`SOUL.md`、原技能目录、将修改的源码及用户服务配置。数据库使用一致性备份；完整备份保留在目标实例，不上传本仓库。
2. 将 `config.overlay.yaml` 的键递归合并进现有 `$HERMES_HOME/config.yaml`（默认 `~/.hermes/config.yaml`），保留模型、认证、连接器和其他既有配置。不要用此覆盖文件直接替换完整配置。
3. 将 `SOUL.additions.md` 的两个章节合并进现有 `SOUL.md`，避免重复追加。保留原有人设和规则。
4. 将技能目录复制到 `$HERMES_HOME/skills/devops/host-health-observation/`。先备份已有同名技能。
5. 在匹配版本的 Hermes 源码仓库中，先运行 `git apply --check /path/to/hermes-recovery.patch`，通过后再运行 `git apply /path/to/hermes-recovery.patch`。升级版本应重新检查兼容性，不能强行应用。
6. 执行相关恢复测试，安排正常的网关重启以加载配置与源码，并检查服务状态和新会话规则加载。本次部署由原生重启流程生成的服务停止超时为 80 秒，不应跨环境盲目复制服务单元。
7. 按技能说明，用全新任务目录启动真实五分钟采样，创建两条一次性定时跟进，核验报告、实际 cron 执行、采样进程退出及任务停用。

回退时恢复本次操作前的配置、SOUL 和技能备份。源码补丁仅在反向检查通过且没有后续冲突时使用 `git apply --reverse --check` / `git apply --reverse`，否则按备份和差异手工恢复。正常重启后再次验证。存档文件本身不会修改或重启服务器。
